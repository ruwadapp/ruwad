# خطة بوابات المعاهد (White-Label Portals)

> **الفكرة المحورية:** منصة رُوّاد تبقى واحدة — قاعدة بيانات واحدة، حسابات مركزية، وإشراف كامل لمدير المنصة (super admin) على كل شيء. المعهد المشترك يحصل على **بوابة بهويته** (دومين + ألوان + شعار) هي نافذة على نفس النظام، وليست نسخة منفصلة. صلاحيات المعهد تشغيلية فقط (طلابه، كورساته، مدربوه)، أما إدارة البوابة/الاشتراك نفسها فحصراً بيد مدير المنصة.

---

## المبادئ الحاكمة (غير قابلة للتفاوض)

1. **مركزية البيانات:** كل حساب يُنشأ عبر أي بوابة يُسجَّل في جداول المنصة المركزية ويظهر فوراً في لوحة super admin.
2. **الاشتراك بيد المنصة:** إنشاء البوابة، تفعيلها، إيقافها، تاريخ انتهائها — عمليات super admin حصراً. المعهد يرى إعدادات بوابته للقراءة فقط.
3. **حساب الطالب واحد عبر الشبكة:** التسجيل عبر بوابة معهدٍ ما لا يحبس الطالب فيه؛ يستطيع لاحقاً الالتحاق بمعاهد أخرى من المنصة الأم. البوابة توسمه بمصدر التسجيل فقط.
4. **الإيقاف الفوري:** إيقاف البوابة من لوحة super admin يعرض صفحة «البوابة غير نشطة» فوراً على دومين المعهد (أداة تحصيل الاشتراك).
5. **لا إعادة هيكلة لاحقة:** كل جدول جديد يُبنى بعمود `institute_id` منذ اليوم الأول.

## المرحلة 0 — قرارات وتهيئة

- [x] **قرار تجربة الطالب داخل البوابة — مُعتمد: «الهوية تتبع البوابة، لا الطالب»:**

  | من أين دخل الطالب؟ | ماذا يرى؟ | الألوان |
  |---|---|---|
  | من `www.ruwaad.app` | منصة رُوّاد الكاملة: كل معاهده وكورساته، الرواق العام، فرص العمل | هوية رُوّاد |
  | من بوابة معهدٍ هو منضم له | تجربته الكاملة (الرئيسية، التقويم، الإنجازات، الدردشات) **مقصورة على محتوى هذا المعهد** | هوية المعهد |
  | من بوابة معهدٍ ليس منضماً له | الواجهة العامة للمعهد + دعوة للانضمام | هوية المعهد |

  قواعد مرافقة:
  - الحساب واحد مركزي دائماً؛ النقاط والنجوم والشهادات موحّدة أينما دخل. البوابة عدسةُ تصفية وعرض، لا عزلُ بيانات.
  - الأقسام العابرة للمعاهد (الرواق العام، «بالقرب مني»، طلبات التدريب العامة) **تُخفى** من قوائم البوابة حفاظاً على العزل البصري؛ الأقسام الشخصية (إنجازاتي، تقدّمي) تبقى كاملة *(قابل للمراجعة عند التنفيذ)*.
  - جلسة كل دومين مستقلة (كوكي البوابة على دومينها) — فمن سجّل عبر البوابة تبقى وجهته الافتراضية تلقائياً.
  - الهدف النهائي هو التجربة الكاملة الملوّنة أعلاه؛ يجوز الشحن المرحلي (واجهة عامة + تسجيل، ثم انتقال للمنصة الأم) كخطوة انتقالية فقط.
- [ ] تسجيل wildcard `*.ruwaad.app` في DNS وفي إعدادات دومينات مشروع Vercel.
- [ ] إنشاء `VERCEL_TOKEN` + `VERCEL_PROJECT_ID` في متغيرات البيئة (لربط الدومينات برمجياً).

## المرحلة 1 — البنية التحتية للبيانات

**جدول `institute_portals`** (سجل الاشتراك — يديره super admin حصراً):

| العمود | النوع | ملاحظات |
|---|---|---|
| `id` | uuid PK | |
| `institute_id` | uuid FK → institutes | unique — بوابة واحدة لكل معهد |
| `subdomain` | text unique | `alnour` ← `alnour.ruwaad.app` |
| `custom_domain` | text unique null | `alnour-academy.com` |
| `domain_status` | text | `none / pending_dns / active` |
| `status` | text | `active / suspended / expired` |
| `expires_at` | timestamptz null | تاريخ انتهاء الاشتراك |
| `brand` | jsonb | `{primary, secondary, accent, navy, logo_url, display_name, favicon_url}` |
| `notes` | text | ملاحظات إدارية داخلية |
| `created_at / updated_at` | timestamptz | |

**تعديلات على جداول قائمة:**
- `profiles.signup_portal_id uuid null` — وسم بوابة إنشاء الحساب (للإحصاء ولوحة super admin).

**RLS:**
- `institute_portals`: **select** لمالك/إدارة المعهد على بوابته فقط + super admin؛ **insert/update/delete** لـ super admin حصراً.
- دوال مساعدة SECURITY DEFINER عند الحاجة، مع `revoke public/anon` + `grant authenticated` + `notify pgrst, 'reload schema'` (النمط المعتمد).

**اختبار القبول:** جلسات محاكاة RLS (النمط المعتمد `set_config` + `set local role authenticated`) تثبت أن المعهد يقرأ بوابته ولا يعدّلها، وأن معهداً آخر لا يراها.

## المرحلة 2 — التعرف على البوابة (Middleware) والهوية البصرية

1. **Middleware:**
   - قراءة `Host` ← إن كان `www.ruwaad.app` فالسلوك الحالي بلا تغيير.
   - وإلا: مطابقة subdomain أو custom_domain في `institute_portals` (عبر استعلام خفيف/كاش) ← حقن `x-portal-id` و`x-institute-id` في headers داخلية.
   - بوابة `suspended/expired` ← rewrite لصفحة «البوابة غير نشطة» (تصميم محايد + وسيلة تواصل المعهد مع إدارة المنصة).
   - دومين غير معروف ← تحويل للمنصة الأم.
2. **تحويل ألوان Tailwind لمتغيرات CSS:**
   - `tailwind.config.ts`: `ruwad-blue: 'var(--brand-primary)'` ... مع قيم افتراضية = هوية رُوّاد الحالية. **لا تغيير في أي صفحة** (أسماء الفئات ثابتة).
   - حصر الألوان الـ inline hex (بطاقات الحضور، الرسوم...) وتمريرها عبر المتغيرات نفسها.
3. **الحقن في `app/layout.tsx`:** قراءة headers البوابة ← جلب `brand` ← `<html style="--brand-primary:...">` + شعار واسم البوابة في المواضع العامة + favicon ديناميكي.
4. **صفحة عامة للبوابة:** الجذر على دومين المعهد = صفحة المعهد (المبنية على `/i/[id]` الحالية) بهويته: كورساته المنشورة، تواصله، زر تسجيل/دخول.

**اختبار القبول:** فتح `alnour.ruwaad.app` يعرض صفحة المعهد بألوانه وشعاره؛ فتح المنصة الأم يعرض هوية رُوّاد بلا أي تغيير؛ إيقاف البوابة يعرض صفحة التعليق فوراً.

## المرحلة 3 — التسجيل والدخول عبر البوابة

- نموذج التسجيل الحالي نفسه على دومين البوابة، مع خلف الكواليس:
  - إنشاء الحساب مركزياً كالمعتاد.
  - `profiles.signup_portal_id` = البوابة الحالية.
  - ربط تلقائي بالمعهد في `institute_members` (طالب، بحالة الانضمام المعتمدة في تدفق المعهد الحالي).
- الدخول عبر البوابة يعمل بنفس المصادقة المركزية.
- **بعد الدخول (وفق القاعدة المعتمدة):** الطالب المنضم للمعهد يبقى داخل البوابة بتجربته الكاملة الملوّنة والمقصورة على محتوى المعهد، مع إخفاء الأقسام العابرة للمعاهد من قوائمها؛ وغير المنضم يرى الواجهة العامة ودعوة الانضمام. (يجوز مرحلياً: تحويل للمنصة الأم بعد الدخول، ثم الترقية للتجربة الكاملة.)

**اختبار القبول:** حساب أُنشئ عبر البوابة يظهر فوراً في لوحة super admin موسوماً بمصدره، ويظهر عند المعهد في طلابه، ويستطيع صاحبه لاحقاً الالتحاق بمعهد آخر من المنصة الأم بنفس الحساب.

## المرحلة 4 — لوحة super admin: إدارة البوابات

قسم جديد «البوابات» في `(superadmin)`:
- إنشاء بوابة لمعهد: اختيار المعهد، subdomain، الهوية (منتقيات ألوان + رفع شعار + **معاينة حية**)، تاريخ الانتهاء.
- أزرار: تفعيل / إيقاف / تمديد، وتعديل الهوية.
- **ربط الدومين الحقيقي:** إدخال الدومين ← استدعاء Vercel Domains API (`POST /v10/projects/{id}/domains`) ← عرض سجلات DNS المطلوبة (A: `76.76.21.21`، CNAME: `cname.vercel-dns.com`) ← زر «تحقق الآن» يستطلع `GET .../config` حتى `active` (شهادة SSL تلقائية) ← زر فك الربط (`DELETE`).
- مؤشرات لكل بوابة: عدد الحسابات القادمة عبرها، آخر نشاط، حالة الدومين.

**ملاحظة:** استدعاءات Vercel API تمر عبر مسار خادم داخلي (`app/api/portals/...`) محمي لدور super admin — التوكن لا يصل المتصفح أبداً.

## المرحلة 5 — واجهة المعهد (قراءة فقط)

في لوحة المعهد قسم «بوابتي»:
- عرض الحالة، الدومين، تاريخ الانتهاء، الهوية الحالية — **بلا أي تحرير**.
- تعليمات DNS الجاهزة للنسخ إن كان الدومين قيد الربط.
- زر «طلب تعديل/تجديد» يفتح تواصلاً مع إدارة المنصة (واتساب/نموذج).
